# Ноды Lumina: справочник

Справочник по типам нод графа реактивного света. Описывает каждый тип: входы
и выходы (хендлы), параметры, поведение в движке, запись в DMX и грабли.

**Источники правды (на 16.08.2026):** `web/App.tsx` (регистрация типов
`nodeTypes` :59, дефолты `addNode`), `web/utils/graphEngine.ts` (движок),
`web/nodes/*.tsx` (компоненты), `web/constants.ts` (раскладки приборов),
`web/utils/lightEngine.ts`, `web/utils/midiTrackConfig.ts`.

---

## 1. Как устроен граф (общая механика)

### Значения и потоки

- Каждая нода вычисляет **массив чисел 0–255** и кладёт его в
  `nodeValues[node.id]`. По рёбрам значение идёт к нодам-потребителям.
- **Входы (target-хендлы) — слева, выходы (source-хендлы) — справа**
  (правило раскладки, 27.07).
- На один входной хендл можно повесить **сколько угодно рёбер**; если вход
  принимает максимум — берётся `Math.max(...)`, иначе значения миксуются
  стратегией ноды (`mixing`).
- Значение на хендле-источнике выбирается по его id через
  `resolveSourceIndex` (`low/mid/high` → 0/1/2, `prefix-N` → N, иначе 0).

### Тики

Движок `evaluateGraph()` гоняется из Worker-тикера **каждые 16 мс (~62 Гц)**.
Порядок вычисления задан `startOrder` (graphEngine.ts:69):
`input → midi → group-activator → math → audio → generator → … → fixture`.
Ноды, которые пишут в DMX напрямую — только `fixture` и `comb-controller`
(+ `midi-track`). Остальные только отдают значения по рёбрам.

### Группы и активность

- `group` (0–255): нода активна, если `activeGroups.has(group)`. Группа **0
  активна всегда**. Неактивная нода гасится (пишет 0) — для записывающих нод
  это значит «вообще ничего не пишет» (см. 26.07-граблю про «головы
  двигаются от выключенной ноды»).
- `group-activator` включает группу при сигнале `> 127` (не `> 0`!).
- `midi`-нода гасится дважды: и группой, и собственным `params.group`.

### Запись в DMX (HTP-мерж)

- Общий буфер — `dmxAggregator[ch]`, куда ноды **дописывают максимум**
  (`finalVal > existing`). Это HTP-мерж: несколько источников на один канал
  суммируются как максимум, а не заменяют друг друга.
- Исключение: `override` (comb-controller/midi-track) и парковка мотора —
  безусловная замена.
- Яркостные типы каналов проходят `blackFloor` (`DMX_BLACK_FLOOR = 3`):
  значения <3 обнуляются. Каналы моторов/скорости/fx НЕ проходят
  (там 1–3 — легальная позиция).
- После всех нод каналы наклона (`comb_rgbw` offset 0) клипуются через
  `applyTiltGuard` в безопасный сектор калибровки; осиротевшие каналы гасит
  `ownedChannelsRef`; blackout пишет все 512 нулями.
- Две ноды с пересечением адресов → бейдж **DMX CONFLICT!** (но пишут обе,
  максимумом).

### Физика моторов (критично)

У расчёски (43ch) `offset 0 = MotorY`, ход 180°. Замер на сцене:
**0 = луч в зал, ~128 (середина) = вверх/вертикаль, 255 = край внутрь сцены**.
Опасна зона у нуля. Старый комментарий «255 = вверх» в коде — НЕВЕРЕН.
Безопасный сектор берётся из калибровки `/api/calibration`
(дефолты `safeLo:64, safeHi:255, park:128`).

## 2. ВХОД — аудио (тип `input`)

**Назначение:** источник аудио для графа — живой микрофон или файл MP3.
Считает три спектральные полосы (LOW/MID/HIGH) и рисует FFT-визуализатор
(WebGL, 32 лог-полосы).

**Входы:** нет.

**Выходы:**
| Хендл | Значение |
|---|---|
| `low` | LOW, бас 20–250 Гц |
| `mid` | MID, середина 250 Гц – 4 кГц |
| `high` | HIGH, верх 4–16 кГц |

**Параметры:**
- `mode` — `'file'` (MP3) | `'live'` (микрофон).
- `fileName` — имя загруженного файла.
- `deviceId` — ID микрофона для live.
- `gain` (LED Level, слайдер 0.1–10) — **влияет только на подсветку крыла и
  индикатор ноды, НЕ на значения в графе**. В граф уходят сырые уровни.

**Поведение:** `inputAudioManager.sample()` в Worker-тикере 16 мс:
`getByteFrequencyData` → три полосы (fftSize 2048, smoothing 0.5).
`outputs = [low, mid, high]`.

**DMX:** не пишет. Сырые полосы идут на подсветку крыла (`wing_leds`,
~10 Гц) через `handleAudioLevelsUpdate` — вот там применяется `gain`.

**Грабли:** blob-URL файла ревокается при смене; при удалении ноды —
`inputAudioManager.destroy(id)`.

## 3. MIDI — MIDI-вход (тип `midi`)

**Назначение:** читает CC/NOTE/PITCH с выбранного устройства (вкл. виртуальное
USB-крыло grandMA), learn-режим, toggle-режим, гашение по группе.

**Входы:** нет (подключение к `group-activator` проверяется по рёбрам).

**Выходы:**
| Хендл | Значение |
|---|---|
| `out-0` | одно значение 0–255 |

**Параметры:**
- `channel` — MIDI-канал 1–16.
- `type` — `'cc'` | `'note'` | `'pitch'`.
- `index` — CC#/Note# 0–127.
- `mode` — `'momentary'` (положение) | `'toggle'` (по фронту >127 инвертирует 0↔255).
- `deviceId` — `'ALL'` (Omni) или ID устройства; `deviceName` — для
  авто-восстановления.
- `group` — 0–255 (0 = всегда активна).
- `isActive` — runtime (мутирует движок).

**Поведение:** состояние в `midiState[\`deviceId__ch-type-idx\`]`, фолбэк на
Omni-ключ. NOTE: 0x90 → 127, 0x80 → 0; вход крыла: fader→CC ch1,
encoder→CC ch2, button→NOTE ch1. В `toggle` шлёт MIDI-фидбек на устройство.

**DMX:** не пишет.

**Грабли:** монитор-колбэк троттлен 100 мс (энкодер шлёт сотни сообщений/сек);
опрос устройств каждые 1.5 с; после отказа прав не ддосит `init()`.

## 4. DSP — сплиттер полос (тип `audio`)

**Назначение:** принимает сигнал и выдаёт те же 3 полосы с обработкой:
усиление (Boost), гейт (Floor) и огибающие attack/drop-сглаживание.

**Входы:**
| Хендл | Значение |
|---|---|
| `signal-in` | сигнал (3 полосы или одно значение) |

**Выходы:**
| Хендл | Значение |
|---|---|
| `out-0` | LOW |
| `out-1` | MID |
| `out-2` | HIGH |

**Параметры:**
- `gain` (Boost) — 0..10, step 0.1 (дефолт 1).
- `gate` (Floor) — 0..255, step 1 (дефолт 0): ниже порога жёсткий 0.
- `attackSmoothing` — 0..0.99 (дефолт 0).
- `decaySmoothing` — 0..0.999 (дефолт 0.9).

**Поведение:** если источник отдаёт ≥3 значений и его source-хендл не содержит
`-` (это input-нода с пинами low/mid/high) — берёт все 3 полосы как есть;
иначе одно значение реплицируется в три огибающие. Далее:
`target = val * gain`; `target < gate → 0`; одно-полюсное сглаживание:
рост через `attackCoeff = 1 - attackSmoothing`, спад через
`dropCoeff = 1 - decaySmoothing`, память — в `node.data.values`.

**DMX:** не пишет.

**Грабли:** дефолт `decay: 0` из `App.tsx` — мёртвый ключ, движок читает
только `decaySmoothing`/`attackSmoothing`.

## 5. LFO — генератор (тип `generator`)

**Назначение:** периодический сигнал с выбором формы и дискретным режимом
0/255.

**Входы:** нет.

**Выходы:**
| Хендл | Значение |
|---|---|
| `out-0` | одно значение 0–255 |

**Параметры:**
- `shape` — `sine` | `triangle` | `saw` | `square` | `noise`.
- `speed` — BPM, слайдер 10–480 (дефолт 120; в UI показывается `Hz = BPM/60`).
- `discrete` — bool: квантование в ровно 0 или 255 (по порогу 127).

**Поведение:** `freq = speed/60`; фаза `_phase` накапливается по реальному
времени (`Date.now()`). Защита от свёрнутой вкладки: если `dT > 0.5` —
`dT = 0.025`. Формы: sine `(sin+1)/2*255`, triangle, saw `p*255`,
square `phase<π ? 255 : 0`, noise `Math.random()*255`.

**DMX:** не пишет.

**Грабли:** слайдер скорости пишет в params при драге, коммит на pointerup;
tap-tempo: до 5 тапов, сброс при паузе >2.5 с, BPM клампится в 10..480.

## 6. MATH — математика (тип `math`)

**Назначение:** смешивает входы выбранной функцией, умножает на `scale`
и сдвигает на `offset`.

**Входы:**
| Хендл | Значение |
|---|---|
| `in-0` | сколько угодно рёбер (все входящие рёбра ноды) |

**Выходы:**
| Хендл | Значение |
|---|---|
| `out-0` | `[final]` (0–255, зажимается снизу: `<0 → 0`) |

**Параметры:**
- `mixing` — `max` | `sum` | `mult` | `avg` | `sub` | `div` | `min`
  (7 кнопок в UI; в `types.ts` есть ещё `last`).
- `scale` (STRENGTH) — 0..10, step 0.1 (дефолт 1).
- `offset` (SHIFT) — −255..255, step 1 (дефолт 0).

**Поведение:** `raw = mix(inputs, mixing)` → `final = raw*scale + offset` →
`outputs = [final < 0 ? 0 : final]`. Формулы: sum — арифм. сумма; mult —
`res * (v/255)`; sub — `res - v`; div — `res / (v/255 || 1)`.

**DMX:** не пишет.

**Грабли:** рёбра с source-хендлом `fix-*` игнорируются.

## 7. GRP ACT — активатор группы (тип `group-activator`)

**Назначение:** включает группу (1–255) при входном сигнале > 127; с опцией
SOLO побеждает только последняя активированная группа.

**Входы:**
| Хендл | Значение |
|---|---|
| `signal-in` | сигнал (порог активации > 127) |

**Выходы:** нет (влияет на граф глобально через `activeGroups`).

**Параметры:**
- `targetGroup` — 1..255 (дефолт 1).
- `solo` — bool: только последняя активированная группа.
- runtime: `_lastVal`, `_lastActivatedAt`.

**Поведение:** до обхода нод для каждого активатора берётся максимум по
входящим рёбрам. Если источник — `midi`-нода, значение читается из
`midiState` с учётом `toggle`. Активна при `maxInput > 127`. При SOLO в
`activeGroups` попадает только группа с максимальным `_lastActivatedAt`,
иначе — все активные. Группа 0 всегда активна.

**DMX:** не пишет. Только гасит/включает `midi`, `fixture`, `comb-controller`.

**Грабли:** порог `>127` — «нормальные» уровни ниже 128 не включают группу;
`safeTargetGroup` защищает от строковых групп старых проектов (грабля 28.07).

## 8. Прибор (тип `fixture`)

**Назначение:** нода реального DMX-прибора. Каждый канал раскладки = свой
пин; значение канала = микс входов (`mixing`, дефолт max) либо ручной фейдер
(`manualValues[idx]`), если входов нет. Пишет каналы `startChannel + idx`.

**Входы (target):**
| Хендл | Значение |
|---|---|
| `in-${idx}` | по одному на каждый канал раскладки, `idx` = индекс канала. Смещение в DMX = `startChannel + idx` |
| `wash-in` | **только у wash-приборов** (led_par_8ch или кастом с раскладкой master/red/green/blue/white/strobe/fx/speed). **Гейт, не канал** — сам значение не потребляет. Провод от `midi-track out-2` = «прибор участвует в заливке COB» |
| `comb-in` | **только у `fixtureType === 'comb_rgbw'`**. Гейт «расчёска играет», провод от `midi-track out-3` |

**Выходы (source):**
| Хендл | Значение |
|---|---|
| `out-${idx}` | по одному на канал; отдают **сырое** значение канала (после микса, ДО mutes/blackFloor/isActive) |

**Параметры:**
- `fixtureType` — `dimmer` | `led_par` | `led_par_8ch` | `spider` | `spark` |
  `laser` | `comb_rgbw` | `mini_par` | `custom`. При смене типа
  `manualValues`/`mutes` пересоздаются под новую раскладку.
- `customLayout` — `[{offset, label, type}]` для `custom` (конструктор приборов).
- `startChannel` — 1..512 (clamp в UI).
- `group` — 0..255 (0 = всегда).
- `manualValues[]`, `mutes[]`, `currentValues[]` — по длине раскладки.
- `color`, `label`, `isCollapsed` (дефолт: свёрнут при `layout.length > 2`).

**Поведение (case 'fixture'):** для каждого idx: `manual = manualValues[idx]`;
входы на `in-${idx}`; `val = inputs.length===0 ? manual : round(mix(inputs,mixing))`;
`finalVal = (mutes[idx] || !isActive) ? 0 : min(val,255)`; `blackFloor` для
яркостных каналов; `ch = startChannel + idx` в 1..512.

**DMX:** HTP-max в `dmxAggregator[ch]` (запись только если больше текущего).
`mutes[idx]` или неактивная группа → 0.

**Грабли:** чернота-порог 3 только для яркостных типов (мотор/скорость/fx не
трогаем); канал за 1..512 молча пропускается; строковый `group` из старых
проектов → 0 (грабля 28.07); выход отдаёт значение до mute/blackFloor.

## 9. COMB — автономные расчёски (тип `comb-controller`)

**Назначение:** автономное управление всеми расчёсками `comb_rgbw` (43ch):
режимы, цвет, яркость, скорость, рассинхрон, наклон реек (в безопасном
секторе), строб, override, парковка при включении. Живёт сам, без midi-track.

**Входы (target):**
| Хендл | Маппинг |
|---|---|
| `bright-in` | яркость: `(v/255)*2` (0..2) |
| `speed-in` | скорость: `0.1 + (v/255)*2.9` |
| `tilt-in` | угол внутри диапазона: `v/255` |
| `strobe-in` | строб: `v/255` |
| `hue-in` | сдвиг оттенка по кругу: `(v/255)*360°` |
| `sat-in` | насыщенность: `v/255` |

Подключённый вход перебивает ползунок (бейдж «ВХОД»).

**Выходы (source):**
| Хендл | Значение |
|---|---|
| `comb-0` | MotorY первой расчёски (текущий угол наклона) |
| `comb-1` | скорость Y (SpdY) |
| `comb-2` | средняя яркость 10 бимов |
| `comb-3` | строб-флаг: 255 если строб активен, иначе 0 |

Заполняются от первой найденной расчёски. При неактивной/stop ноде — `[0,0,0,0]`.

**Параметры:**
| параметр | дефолт | диапазон |
|---|---|---|
| `mode` | `quiet` | quiet / medium / epic |
| `brightness` | 1 | 0–2 |
| `speed` | 1 | 0.1–3 |
| `randomize` (рассинхрон) | 0 | 0–1 |
| `tilt` (угол в диапазоне) | 0.5 | 0–1 |
| `tiltMin` / `tiltMax` | 128 / 255 | 0–255 (безопасный сектор) |
| `parkTilt` | 255 | 0–255 |
| `strobe` | 0 | 0–1 (кнопка ВКЛ → 0.6) |
| `colorMode` | `rainbow` | кнопки цветов |
| `hueBase` / `saturation` | 0 / 1 | задаются кнопками цвета |
| `override` | false | тумблер (прямая запись вместо HTP) |
| `stop` | false | кнопка ВКЛ/ВЫКЛ |

Пресеты режимов (движок): `quiet` — мотор 0.15, spdY 30, яркость 60–140,
sat 0.4; `medium` — 0.5/90/150–220/0.8; `epic` — 1.2/200/230–255/1.0.

**Поведение:** `isActive = activeGroups.has(group) && !stop`; неактивная —
**не пишет ни байта**. Яркость/скорость/строб/sat из входов или ползунков.
`phase += dT*speed`. Сектор наклона из `tiltMin/tiltMax` (через `clampTilt`,
не из ползунков ноды). **Парковка**: первые 1500 мс мотор едет в `parkTilt`
при нулевой яркости, затем плавный ввод 600 мс. Каждая расчёска: свой seed
(рассинхрон `randomize`), MotorY = угол, SpdY, 10 бимов RGBW с огибающей
`env = intMin+(intMax-intMin)*(0.5+0.5*sin(...))`, hue вращается по радуге,
строб на W-канале (rate `strobe*12`), `Reset` = 0.

**DMX:** адреса из проекта (по умолчанию 250/293/336/379, 43 канала).
HTP-мерж, кроме `override`/парковки — безусловная замена. Канал мотора
потом — через `applyTiltGuard`.

**Грабли:** белый канал W подчиняется `brightness`/`fadeIn` (раньше белые
диоды долбили на 255 при нуле яркости); строб только из явного значения/
входа (пресет не включает тайком); выключенная нода не пишет вообще;
физика: 0 = в зал, 128 = вверх, 255 = внутрь сцены (НЕ «255 = вверх»!).

## 10. ПАЛ — палитра COB (тип `palette`)

**Назначение:** палитра цвета верхнего света (COB): сдвиг оттенка и
насыщенность. Оба параметра можно крутить снаружи (LFO, фейдеры крыла) через
входы; выходы 0–255 уходят в `wash-hue-in`/`wash-sat-in` ноды MIDI-трек.

**Входы (target):**
| Хендл | Значение |
|---|---|
| `hue-in` | сдвиг цвета 0–255 (перебивает ползунок) |
| `sat-in` | насыщенность 0–255 (перебивает ползунок) |

**Выходы (source):**
| Хендл | Значение |
|---|---|
| `out-0` | сдвиг цвета `round(hue*255)` |
| `out-1` | насыщенность `round(sat*255)` |

**Параметры:**
- `hue` — 0..1, step 0.01 (в UI показывается `deg = hue*360`).
- `saturation` — 0..1, step 0.01 (показывается в %).

**Поведение:** `hue = clamp01(inHue/255)`, `sat = clamp01(inSat/255)`; в DMX
сама НЕ пишет — только на выходы, их потребляет midi-track (заливка COB).

## 11. ТРЕК — источник трека (тип `music-track`)

**Назначение:** хранит ссылки на аудио (`audioUrl`) и `analysis.json`
(`analysisUrl`) для ноды MIDI-трек. Закидывает MP3 → сервер сохраняет в
медиатеку и гоняет через music2midi headless (автоанализ).

**Входы:** нет.

**Выходы:**
| Хендл | Значение |
|---|---|
| `out-0` | готовность: 255 = трек загружен И анализ готов, иначе 0 |

**Параметры:** `audioUrl`, `audioName`, `analysisUrl`, `analysisName`,
`notes` (кол-во нот), `duration` (сек).

**Поведение:** `outputs = [ready ? 255 : 0]`. Реальный источник midi-track
читается НЕ через движок, а на уровне компонента: ребро `track-in` →
`useMidiTrack` берёт `audioUrl/analysisUrl` напрямую из params ноды-источника.

**API:** `POST /api/tracks/prepare` (загрузка), поллинг
`GET /api/tracks/prepare/{jobId}` каждые 2 с, `GET /api/tracks/engine`
(прогрев нейросети), `GET /api/stems/list` (медиатека, пометка «📊 готов»).

**Грабли:** модель music2midi живёт на RTX 4090, час простоя — сервер сам её
выгружает; первый прогрев — минуты, поэтому есть кнопка «разогреть нейросеть».

## 12. TRACK — MIDI-трек (тип `midi-track`)

**Назначение:** ядро реактивного света: анализ трека → движок 40 лучей
(RGBW-буфер 160 = 40×4) → 4 расчёски по 10 бимов; плюс заливка COB (`wash`),
плавный фон кулисных RGB-пар (`backstage`), мотор/скорость, партитура (score),
запись автоматизации (● REC), синхрон со входом звукача. Ядро —
`web/utils/lightEngine.ts`, транспорт — `web/services/midiTrackManager.ts`.

**Входы (target, все 0–255, максимум по рёбрам):**
| Хендл | Смысл | Маппинг |
|---|---|---|
| `track-in` | источник (ребро от `music-track out-0`); трек читается из params источника | — (компонентный) |
| `bright-in` | яркость лучей | `/255*2.5` |
| `tilt-in` | статичный наклон головы | `/255` → 0..1 → `tiltMin..tiltMax` |
| `hue-in` | сдвиг цвета лучей | `/255` → 0..1 (wrap) |
| `sat-in` | насыщенность лучей | `/255` → 0..1 |
| `width-in` | ширина пятна | `0.1 + /255*2.9` |
| `release-in` | спад ноты | `0.08 + /255*0.72` с |
| `wash-hue-in` | COB оттенок (от «Палитра COB») | `/255` → 0..1 |
| `wash-sat-in` | COB насыщенность | `/255` → 0..1 |
| `backstage-bright-in` | яркость кулис | `/255*2` (0 может погасить) |
| `backstage-hue-in` | оттенок кулис | `/255` → 0..1 |
| `backstage-sat-in` | насыщенность кулис | `/255` → 0..1 |

**Выходы (source):**
| Хендл | Значение |
|---|---|
| `out-0` | энергия кадра `0–255` = `frame.energy * 40` |
| `out-1` | угол мотора `0–255` (в шкале DMX, в безопасном секторе) |
| `out-2` | мастер-уровень заливки COB `0–255`. Провод на вход `wash-in` прибора LED PAR = гейт «прибор участвует»; без проводов — все найденные |
| `out-3` | «ЛУЧИ» — та же энергия кадра; провод на `comb-in` расчёски = гейт «расчёска играет»; без проводов — все найденные |
| `out-4` | «КОНЕЦ ТРЕКА» — проигрывает `endPattern` (массив шагов `{v,ms}`, 0-255) в последние `endSeconds` (дефолт 3), после окна — `0`. Дефолт = 3 мигания по 0.6 с (ВКЛ/ВЫКЛ/ВКЛ/ВЫКЛ/ВКЛ/ВЫКЛ). Универсальный примитив: любой паттерн (мигание/дим/строб). Провод на `master-in` пульта KKZ = мигание света в конце трека; на `off-in` = одно выключение |

> Role-шин kick/snare/hats/bass/harmony/lead/all и отдельных выходов
> `backstage.wash`/`combs` в коде НЕТ (в отличие от более ранних заметок
> `docs/reactive-light-midi.md`). Роль ударных выполняют профиль трека и
> `backstageDrums()`; комбы гейтятся проводами out-3→comb-in.

**Параметры** (единая фабрика `web/utils/midiTrackConfig.ts`):

- **Источник:** `audioUrl/audioName/analysisUrl/analysisName`.
- **Управление:** `stop`, `group`, `override` (true = прямая запись,
  false = HTP).
- **Синхрон:** `syncOn`, `syncDeviceId`, `syncPair` (`'0'` | `'2'`).
- **Лучи:** `symmetry` (зеркальная пара), `width` (0.1–3), `release` (спад,
  0.08–0.8 с), `brightness` (0–2.5), `tilt` (0–1), `tiltMin/tiltMax/parkTilt`
  (null → калибровка), `levelSource` (`spec` | `rms`), `palette`
  (`thermal` | `rainbow` | `mono`), `hueShift`, `saturation`, `posMode`
  (`keys` | `walk`), `range` (`dense` = p10..p90 | `full`), `minFlashFrames`
  (1–4, дефолт 2), `gamma` (1.4 — прижимает хвосты PWM), `motorSpeed`
  (0–255, дефолт 80), `parkMs` (1500), `fadeInMs` (600).
- **Заливка COB:** `wash`, `washBrightness`, `washFloor` (0.5), `washStrobe`.
- **Кулисы:** `backstage`, `backstageMode` (`notes` | `comet`),
  `backstageBrightness`, `backstageFloor` (0.35), `backstageSaturation`
  (null → 0.9 / цвет COB), `backstageFlow` (1), `backstageWave` (0.08),
  `backstageHue`.
- **Партитура:** `scoreV1` (добавляется отдельно).
- Runtime-поля `_eff*`, `_driven`, `_activeSince` — при сохранении вырезаются
  `stripMidiTrackRuntime`.

**Поведение:** `isActive = activeGroups.has(group) && !stop`; выключенная нода
**не пишет ни байта**. Входы — максимум. Модификаторы: `scoreMods`
(яркость ×, оттенок wrap, sat/наклон clamp, gate) и `scoreAutomation`
(абсолютные кривые замещают слайдер, но уступают подключённому входу).
Парковка: первые `parkMs` мотор в `parkTilt` при нулевой яркости, свет
вводится `fadeInMs`; во время парковки запись безусловная, иначе HTP.
`midiTrackManager.render()` → `frame {px, motor, energy}`. Стоп/нет анализа →
`outputs=[0,128,0,0]`.

**DMX-запись:**
- **Расчёски** (4×10=40 лучей, сортируются по `startChannel`, риг 250/293/
  336/379): `startCh` = MotorY (при парковке = `parkTilt`), `startCh+1` =
  SpdY (`motorSpeed`), `startCh+2+b*4+0..3` = R,G,B,W луча
  (`blackFloor(round(pow(lin,gamma)*255*fadeIn))`), `startCh+42` = 0.
- **COB** (`led_par_8ch`): +0 Master, +1 R, +2 G, +3 B, +4 W, +5 Строб
  (max-merge). Заливка в нуле, пока расчёски паркуются.
- **Кулисы**: режим `comet` или `notes`; запись по типам каналов
  (master/red/green/blue/white; у 6ch нет master — яркость в RGB; strobe/fx/
  speed = 0). Порядок — физический (Front L→R).

**Транспорт:** мастер-клок — `HTMLAudioElement.currentTime` (аудио тянет
свет). Режимы: play (конец → seek(0)), pause (заморозка времени, кадр жив),
stop (гашение, парковка, позиция 0), seek, toggle, mute. **● REC** — только
на играющем треке; без score создаёт каркас из профиля; точки с троттлингом
~10 Гц; stop = автозакрытие; overdub мержит диапазон. Цели REC: лучи
brightness/hueShift/saturation, motion.tilt, backstage brightness/hueShift/
saturation. **Секции/cue/score**: `scoreCompiler.ts`, детерминированный
черновик из профиля (`draftFromProfile`), locked-cue переживают
перегенерацию, устаревший отпечаток = score молча игнорируется.
**Синхрон со звукачом** `audioSyncFollower`: off/starting/locked/coast/silent.

**Грабли:** первый кадр после старта/перемотки `dt=0.016` (иначе уход в
ресинк); `minFlashFrames=2..3` — надёжная вспышка через беспроводной DMX;
парковка — чтобы лучи не ударили в зал, где мотор стоял с прошлого раза;
проекционная шина 10 Гц `{playing, energy, hue, sat, wash, section, hit,
lyricsUrl}`; слайдеры блокируются при подключённом входе (`_driven`) — иначе
нода «врёт» (жалоба 27.07).

## 13. KKZ — реле света (тип `kkz`)

**Назначение:** пульт Tuya-автоматов реле через VPS-сервер: два автомата,
тумблеры = физическое состояние, мастер (свет зала целиком), ФЛЕШ,
управление с других нод через входы.

**Входы (target, 0–255, максимум; −1 = не подключён):**
| Хендл | Смысл |
|---|---|
| `master-in` | «свет зала»: `>127` = ВКЛ ВСЕХ реле, `≤127` = ВЫКЛ ВСЕХ. Стабильный таргет — паттерн-мигание с `midi-track out-4` работает (каждый фронт = команда) |
| `dev-0-in` | прямое вкл/выкл автомата 1 (`>127` = ВКЛ) |
| `dev-1-in` | прямое вкл/выкл автомата 2 |
| `off-in` | ВЫКЛ всех реле **только по фронту `0→255`** (триггер «конец трека»: `midi-track out-4`) |

**Выходы:** нет.

**Параметры:** `url` (дефолт `https://kkz-button.207.174.31.143.sslip.io:8445`),
`pin` (дефолт `3033`), `master: false`.

**Поведение:** движок шлёт `[master, dev0, dev1, off]` каждый кадр; нода
сравнивает с прошлым (`prevIn`) и шлёт HTTP **только по фронту 0↔1** —
молотить Tuya-автоматы каждым кадром нельзя (работают секундами). `off-in`
срабатывает только на фронте `0→255` (стартовый монтаж `−1→0` действия не
даёт), после выключения падение триггера обратно в `0` команду не повторяет.
Тумблеры карточек = **физика**: рисуются прямо из последнего опроса
`/api/status` (5 с) — реле потемнело (выключили с телефона) → тумблер сам
выключился, загорелось → включился. Клик по тумблеру = прямая команда реле
(`/api/batch`), без локальной памяти браузера. `master-in`/`off-in`/ГП
работают по **всем** реле — внешне включённое (телефон) тоже гасится.
ФЛЕШ инвертирует физически горящие.

**HTTP API:** `GET /api/config` (имена), `GET /api/status` (поллинг 5 с:
`[{on, power_w, voltage_v, current_ma}]`), `POST /api/batch`
(`{devices:[i], on, source}`, `source`: `'main'|'flash'|'in'`|`'tray'`),
заголовок `X-Pin`. Все запросы — `AbortController` с таймаутом **4000 мс**;
`403` → «Неверный PIN»; busy-лок против одновременных запросов.

**Электрон/трей** (`web/electron/main.cjs`): `kkzSetPower(on)` дёргает оба
устройства source `'tray'`; `kkzGetStatus()` → «свет включён», если включён
хотя бы один; оба с 4-с таймаутом; меню трея обновляется при каждом открытии.

**Грабли:** фон в трее — Chromium throttles фоновые таймеры до ~1/мин →
`visibilitychange` перезагружает статус при возврате окна на передний план;
фронт-детект входов против повторных срабатываний.

## 15. PATCH — патч-нода, диспетчер адресов (тип `patch`) (17.08)

Визуальный DMX-патч по образцу «консольных слотов» COB (ALT+N), но в веб-графе.
**Модель A — диспетчер**: патч-нода НЕ хранит структуру рига, а правит
существующие fixture-ноды (`onParamChange(fid, 'startChannel'|'group'|'universe', v)`) и
создаёт/удаляет их (`onAddNode`/`onDeleteNode` из injectHandlers). Источник
правды — сами ноды приборов, поэтому движок, провода и старые проекты не
ломаются. Читает граф живым через `useStore(s => s.nodes)`.

**Модель правки «черновик + Применить» (17.08)** — правки копятся в локальном
черновике (не трогая граф), кнопка **«Применить…»** коммитит всё разом:
модал с именем (дефолт «предыдущее имя + номер +1»), после подтверждения —
`onAddNode` для новых, `onParamChange` для существующих, `onDeleteNode` для
отсутствующих, `params.groups`/`params.stacks` с разрешёнными id, и пресет
сохраняется в `web/utils/patchPresets.ts`. Кнопка **«Сбросить»** — вернуть
черновик к текущему состоянию графа. **Undo-стек** (кнопка ↶): снапшот
`{draft, groups, stacks}` на каждое действие (до 60 шагов).

- **Полотно** — пианоролл по адресам: адреса горизонтальны (прибор занимает
  ширину своих каналов), рулер-линейка 1..512 (метки каждые 20), шахматная
  подложка, линия каждые 10. **Два полотна**: Юниверс 1 (основная линия,
  адреса 1..191) и Юниверс 2 (отдельная линия OUT2, адреса 200..449) — **оба
  редактируемые**, у каждого прибора есть поле `universe` (1|2). Сервер шлёт
  два независимых кадра `send_dmx(frame, frame2)` (см. rig-sozvezdie).
- **Полосы-приборы** раскрашены по типам каналов (intensity/цвет/позиция/
  скорость/fx), цвет рамки — акцент типа прибора. Драг полосы = смена адреса
  (в черновике), клик = выбор, Ctrl/Shift-клик = мультивыбор.
- **Маркеры групп** (красные, номер = твой ALT+N): явный список в
  `params.groups` + производные от приборов. Клик — подсветить связанных.
  Дубли номеров в явном списке → красное предупреждение «одинаковые номера».
  Присвоение группы прибору — поле в тулбаре (`params.group`).
- **Стак в параллель** (спаренные COB на 200 и т.п.): `params.stacks` = массив
  списков id приборов. Движок НЕ помечает такие перекрытия конфликтом
  (`graphEngine` конфликт-детекция: все конфликтующие в одном стаке = ок).
  Тулбар: «⧉ Стак» (по выделенным), «Разстак».
- **Патчи-пресеты (stage)** — полные карты света площадки, в UI называются
  **Stage**. Стор `web/utils/patchPresets.ts`:
  сохранённые в `lumina-stage-patches` + дефолтные **★ Blank** (пустой) и
  **★ ККЗ 17.08.26** (полный патч U1+U2 из `INITIAL_FIXTURES`; группа по
  карте площадки, юниверс: адрес <200 → U1, иначе U2). Дефолтные нельзя
  удалить физически — прячутся через `lumina-stage-hidden` (как дефолты
  банка). **Текущий Stage** показывается селектом в панели действий (выбор =
  загрузка в черновик), кнопка **«Удалить»** (после «Сбросить», с
  подтверждением) удаляет текущий Stage; «Применить» = сохранить под новым
  именем (дефолт «предыдущее + номер +1», первый раз «ККЗ 17.08.26»).
  Статистика по приборам/каналам — в заголовке каждого юниверса.
- **Банк** = библиотека профилей приборов, глобально (localStorage
  `lumina-fixture-bank`, `web/utils/fixtureBank.ts`): 8 шаблонов
  `FIXTURE_LAYOUTS` + кастомные (кнопка «В банк» сохраняет профиль выбранного
  прибора). Драг чипа банка на полотно U1/U2 = создать прибор на этом адресе
  в этом юниверсе. Дефолтные профили удаляются через скрытие
  (`lumina-bank-hidden`).
- **Проверка движка не трогается** (конфликты ≠ стакам подсвечивает красным).
  Сервер/консоль/COB-панель/депо НЕ затрагиваются (зеркальность сохраняется).
